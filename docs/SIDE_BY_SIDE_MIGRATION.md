# 기존 앱을 남겨 두고 New 앱으로 옮기기

새 설치 파일은 **My Travel Diary 2D New 2.0.0**과 **My Travel Diary 3D New 2.0.0**입니다. 앱 ID가 다르므로 기존 2D·3D와 새 2D·3D, 총 네 앱을 함께 설치할 수 있습니다. 기존 앱을 제거하거나 덮어쓰지 않습니다. 새 앱은 Android의 앱 격리 때문에 기존 앱의 저장 공간을 직접 읽을 수 없습니다.

## 여행마다 진행할 순서

1. 기존 앱에서 여행을 열고 ▶ 화면의 **Back up this journey**로 여행 JSON을 다운로드 폴더 등 앱 외부에 저장합니다. 기존 앱에서 사진 포함 ZIP 백업을 제공한다면 ZIP을 사용해도 됩니다.
2. New APK를 설치하고 첫 화면의 **기존 앱의 여행 가져오기 → 백업 파일 선택**에서 해당 파일을 선택합니다. Restore도 같은 기능입니다. JSON·ZIP을 자동 구분합니다.
3. 복원 직후 열리는 **사진 보관·백업**에서 연결 상태를 확인합니다. JSON에는 사진 파일이 없으므로 갤러리 원본이 남아 있어야 합니다. **사진·동영상 접근 허용**으로 원본 접근을 허용합니다. 일부 사진만 허용하면 선택하지 않은 파일은 확인 필요로 남습니다.
4. 읽을 수 없거나 파일 이름이 달라진 항목은 **이 파일 직접 연결**로 정확한 원본을 선택합니다. 기록 속 이름과 선택한 사진을 확인하고 **연결하고 보관**을 누릅니다. 사진·동영상은 새 앱에 복사되며 여행 날짜·위치·수정 내용은 유지됩니다. 파일 이름만 보고 자동으로 대체하지 않습니다.
5. 날짜·경로·장소 이름·직접 수정한 위치·사진·동영상을 실제로 열어 확인합니다. 읽기 가능 개수는 파일에 접근할 수 있다는 뜻이며 내용이 맞다는 보증은 아닙니다.
6. **사진·동영상 모두 앱에 보관**을 눌러 `앱에 보관 N / N개`를 확인합니다. 이어 **사진·동영상 포함 백업**으로 `.travel.zip`을 앱 외부에 저장합니다.
7. ZIP을 다시 가져와 복원과 사진을 확인하고, 백업 파일을 PC나 별도 저장장치에도 보관합니다. 모든 여행을 확인하기 전에는 기존 앱과 갤러리 원본을 유지하세요.

## 보존 범위와 제한

- 복원할 때 여행·방문·이동·미디어 ID를 새로 부여하므로 같은 백업을 여러 번 가져와도 기존 여행을 대체하지 않습니다. 각 사진의 방문·이동 연결과 날짜·사용자 위치 수정 정보를 함께 옮깁니다.
- JSON에 담긴 여행 정보만 옮깁니다. 이전 앱의 별도 설정, 임시 분석 캐시, 자동 대표 사진 선택 결과는 그대로 재현되지 않을 수 있습니다.
- JSON이 가리키는 원본이 삭제되었고 다른 곳에도 없다면 JSON만으로 사진을 복구할 수 없습니다. 이전 앱 내부에만 있는 파일은 그 앱의 내보내기 기능으로 먼저 꺼내야 합니다.
- 앱 보관본은 원본 갤러리와 별개입니다. 그러나 New 앱 또는 해당 여행을 삭제하면 그 보관본도 삭제되므로 외부 ZIP 백업이 필요합니다.
- 사진 포함 ZIP은 2D·3D 양쪽에서 복원할 수 있습니다. 파일당 512 MB, 미디어 합계 2 GB 제한과 백업 준비용 임시 공간이 필요합니다. 제한에 걸리면 기존 원본을 유지하고 별도로 복사하세요.
- 파일을 읽을 수 없으면 사진 포함 백업을 완료로 처리하지 않습니다. 진행 중 취소하면 완료된 보관본은 유지하고 미완성 파일은 정리합니다.

## 업데이트

앱을 열 때 더 높은 버전을 확인해 알림을 표시합니다. 다운로드와 설치는 사용자가 선택합니다. 새 버전 APK와 `update-next.json`을 공식 GitHub 릴리스에 게시해야 작동합니다. [배포 방법](IN_APP_UPDATES.md).
